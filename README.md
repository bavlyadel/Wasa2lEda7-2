# وسائل إيضاح — موقع إدارة الخدمات

موقع عربي متجاوب (موبايل + كمبيوتر) بواجهة داكنة، تسجيل حسابات، جدول خدمات، طلبات أعضاء، ولوحة مسؤول. يستخدم Supabase للمصادقة وقاعدة البيانات مع سياسات RLS.

## الموجود في النسخة الأولية
- إنشاء حساب عضو وتسجيل الدخول بالبريد وكلمة المرور.
- جدول خدمات مشترك للمستخدمين المسجلين.
- المسؤول يضيف خدمة ويعيّن عضوًا بالبريد الإلكتروني.
- العضو يرسل طلب تبديل/اعتذار/استفسار ويتابع حالته.
- المسؤول يراجع الطلبات ويوافق أو يرفض.
- حماية على مستوى قاعدة البيانات: العضو لا يستطيع إضافة خدمات أو مراجعة طلبات الآخرين أو منح نفسه صلاحية مسؤول.

> هذه نسخة أولية قابلة للتشغيل بعد الربط بـ Supabase. وظائف الفيديو التي لا يمكن تأكيدها من اللقطات (مثل قواعد التوزيع التلقائي الدقيقة أو تقارير/تصدير خاص) تحتاج تحديد قواعدها ثم إضافتها.

## 1) إنشاء قاعدة البيانات
1. افتح https://supabase.com وأنشئ مشروعًا جديدًا.
2. من لوحة المشروع افتح **SQL Editor** ثم **New query**.
3. انسخ كل محتوى `supabase.sql` وشغّله.
4. من **Project Settings → API** انسخ **Project URL** و **anon/public key**. لا تستخدم `service_role` key في الواجهة مطلقًا.

## 2) ربط الموقع
افتح `app.js` واستبدل:
- `https://YOUR_PROJECT.supabase.co` برابط مشروعك.
- `YOUR_SUPABASE_ANON_KEY` بمفتاح anon/public.
احفظ الملف.

## 3) إنشاء أول مسؤول
1. انشر الموقع مؤقتًا أو افتحه محليًا عبر خادم محلي (لا تكتفِ بفتح الملف بالنقر المزدوج إذا واجه المتصفح مشكلة).
2. أنشئ حسابًا من واجهة الموقع ببريد المسؤول.
3. في Supabase افتح **SQL Editor** وشغّل، بعد استبدال البريد:
   ```sql
   update public.profiles
   set role = 'admin'
   where lower(email) = lower('admin@example.com');
   ```
4. سجّل الخروج ثم الدخول مجددًا. سيظهر قسم إدارة الموقع.

## 4) النشر أونلاين (Netlify — طريقة سهلة)
1. أنشئ حسابًا على https://www.netlify.com/
2. ارفع مجلد الموقع `wasael_eydah` أو اسحب محتوياته إلى صفحة النشر اليدوي في Netlify (Deploy manually / drag and drop).
3. ستحصل على رابط عام من نوع `https://something.netlify.app`.
4. في Supabase افتح **Authentication → URL Configuration**، واجعل رابط Netlify هو **Site URL**، وأضفه إلى **Redirect URLs**.
5. جرّب إنشاء حساب، تأكيد البريد إن كان التحقق مفعّلًا، تسجيل الدخول، إضافة خدمة كمسؤول، ثم إرسال طلب من حساب عضو آخر.

## 5) قواعد الأمان
- رابط الموقع عام، لكن صفحات البيانات تتطلب تسجيل دخول.
- صلاحية المسؤول تتحقق في قاعدة البيانات، وليس بمجرد إخفاء عناصر الواجهة.
- لا تضع أبدًا `service_role` key أو كلمة مرور قاعدة البيانات في `app.js`.
- استخدم كلمات مرور قوية، وفعّل تأكيد البريد في Supabase.
- النسخة الحالية تعرض جدول الخدمات للمستخدمين المسجلين؛ لا تضع معلومات شخصية حساسة في الملاحظات.
- قبل الاستخدام الفعلي على نطاق واسع، راجع سياسات الخصوصية، النسخ الاحتياطي، وسياسات الوصول وفق احتياجات الكنيسة.

## الملفات
- `index.html`: بنية الصفحات.
- `style.css`: التصميم المتجاوب.
- `app.js`: المصادقة والعمليات.
- `supabase.sql`: الجداول والصلاحيات والسياسات.
